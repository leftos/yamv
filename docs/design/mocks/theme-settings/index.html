YAMV: theme settings window

The visual editor from look.md, in four states. Each lane is the whole window at 980 × 640. The window's own chrome takes the theme in use; the right pane is the live preview of the theme being edited. Every colour, font and size here is a real Studio token from ThemeTokens.cs unless a note says otherwise.

A · A built-in theme: Studio, light

Built-in themes are read-only. Every field is disabled, and the footer offers Duplicate to edit where Save would be.

  • The token list is shown scrolled to the end (Syntax, Type, Layout) to show every kind of field: colour swatch with a hex field, a font box, a number box with its unit, and a checkbox. Lane B shows the top.
  • Studio sets no tokens of its own, so every value is a default, drawn in grey as an inherited value.
  • Duplicate to edit writes studio-2.yamv-theme.json named "Studio (copy)" into Yours and selects it, ready to edit.
  • Edit as text is off: a built-in theme has no file on disk to open.
  • Clicking a theme in the list makes it the theme in use. Appearance (Match system / Light / Dark) sits at the foot of the list, since it picks which half of the theme the app shows.

B · Your theme: My Studio, dark, with an unsaved change

A user theme in Yours is editable. The Dark tab is open, and the accent's picker is open with a new green. Revert and Save are on because the change is not saved yet.

  • Each tab shows the full resolved value of every token. Grey values come from Shared or the Studio defaults; bright values are set in this tab and have a ↺ that removes them from the tab.
  • An unsaved token gets an accent dot after its name, and the title bar gets one after the theme name.
  • Clicking a swatch opens the picker: a saturation square, hue, alpha (themes accept #rrggbbaa), the hex field and the old/new colours side by side.
  • The preview follows every keystroke (the green link and the green selection bar in the tree). The window's own chrome keeps the saved theme until Save.
  • Revert drops every unsaved change back to the file on disk. Save writes the file; the folder watcher then re-applies it like any outside edit.

C · The Import notice

Import… opens a file picker, then this notice before anything is copied into the themes folder. The wording comes from the trust model in themes.md.

  • It shows every time, whether or not the file holds css; the header line says whether it does.
  • The file card reads the theme's name, author, halves and whether it has css from the file before import.
  • Import is the default button. A taken id is imported as <id>-2 without asking, as themes.md says.
  • Drawn as a modal over the settings window, in the window's own theme.

D · A user theme that failed to load

nord.yamv-theme.json in the themes folder has two bad tokens. The list marks it with a warning glyph; selecting it shows its errors and Edit as text instead of the token editor.

  • The row is greyed with the warning glyph in every state (lanes A to C show it too). Selecting it inspects it but does not make it the theme in use; the app stays on the last good theme.
  • The errors are the parser's own messages, one per line.
  • The watcher re-reads the file on every save, so fixing it in the editor turns the row normal and brings the token editor back.
  • No tabs, no preview, and Export, Revert and Save are off: there is no valid theme to show or write.
