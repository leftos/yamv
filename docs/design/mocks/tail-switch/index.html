YAMV: the Tail switch, three ways to follow a growing document

Ruled: a document short enough to fit in the view is at both its top and its bottom, and on a reload the top pin wins, so a short file that grows stays at its top. A Tail switch the user turns on makes the view follow appended text instead, as tail -f does. Each lane answers the open parts together: where the switch lives, whether it is per document or per window, whether it survives a restart, what turns it off, and how you see that it is on.

Every frame is a Studio main window at its real size, scaled down. The open document, nightly.md, is a build log a script appends to every few seconds. Time runs down the page: first the window following the log, then the same window after you scroll up to read an earlier run while three more lines arrive below. The last rows show the switch up close, in light and dark. Orange marks are annotations, not UI.

Recommended: lane A, a Tail button in the title bar, per document, remembered It sits beside ⟷, the other way you set how this document is shown, so it is found without knowing a shortcut. The file is what grows, not the window, so the switch belongs to the document and comes back on with it after a restart. Scrolling up only pauses it: you can read back freely, the pill says new text arrived and takes you to it, and reaching the bottom picks the follow up again. Its cost is one more button in every window, and a paused button that differs from a lit one only by its fill.
