YAMV: a document that exists but can't be read

You select README.md in the tree, but another program holds it locked (or access is denied). Today the title bar switches to README.md while the page keeps showing MAIN.md, and nothing says the read failed. Each lane is the whole window in Studio light; beside it is the document pane alone in Studio dark.

A · Keep the previous page, with a warning strip

The selection and the title move to README.md. The page stays on MAIN.md under a strip that says why it did not change.

Studio light full window

Studio dark pane only, access denied

Retry reads README.md again: if it reads, the strip goes and the page shows README.md; if not, the strip stays. YAMV also watches the file and swaps the page in by itself once it becomes readable.

B · A "can't read" pane in place of the page

Modelled on the missing-document pane. The tree row stays normal (not greyed), with a small warning glyph while the read fails.

Studio light full window

README.mdyamv
Studio dark pane only, access denied

Retry reads README.md again; if it reads, the document replaces this pane and the glyph leaves the row. When the file changes (the other program saves or lets go), YAMV retries by itself and the pane gives way the same way.

C · Selection does not move; a notice says why

The highlight, the title and the page all stay on MAIN.md. A notice at the bottom-right of the document pane shows for 4 seconds.

Studio light full window

MAIN.mdyamv / docs / plans
Studio dark pane only, access denied

There is no Retry: clicking README.md again is the retry. Nothing waits on the file, so once it becomes readable it stays unopened until it is clicked again.
